## 이번 판을 만든 근거

**공식 일정표(11/18, [Lifestyle ⑩] 피칭 가이드 & Lifestyle 피칭 데이 - 인터랙티브 발표):** 정적 PPT → 브라우저에서 돌아가는 인터랙티브 HTML 발표(애니메이션·라이브 차트·데모 임베드) / Claude Code + 슬라이드 스킬(frontend-slides 등)로 개요 → HTML 피치덱, PDF는 백업용 / 피치 구조(문제-해결-시장-BM-MVP-팀-요청사항)와 라이브 데모 요령 / (오후) 팀별 피칭·피드백 2.5시간 / [크] 키비주얼·숏폼을 발표 흐름에 녹이는 연출, 로컬 IP × K-웰니스 기획전 피치 / [데] 라이브 차트(Chart.js), 개인화 추천 × 수요예측 서비스 피치 / 도구: NotebookLM(오디오 오버뷰 리허설), Vercel / 결과물: HTML 인터랙티브 피치덱(URL), 발표 피드백 시트.

**이 판의 자리:** 11/15 밤 두 세션을 합치며 강사님이 고른 Day 18이에요(HANDOFF 7-25). 다른 세션의 팀 발표판(7-24, 같은 링크의 앞 버전)은 쓰지 않아요.

**강사님 문답(11/15)**
- 피칭: **개인별**. 조 안에서 먼저(한 사람 3분) → 조 대표만 반 전체 앞(5분 + 질문 3분)
- 링크: **아티팩트가 기본, Vercel은 선택**
- 피드백: **전체 발표는 구글 폼(강사님이 만듦), 조 안 발표는 피드백 카드 페이지.** 처음에는 "한 화면에 쌓이는 피드백 페이지"를 고르셨는데, 링크로 들어온 학생은 아티팩트에 글을 저장할 수 없어서(강사님과 이메일로 편집자 초대를 받은 사람만 저장 가능) 바꿨습니다.
- 숏폼 티저: 내 MVP 소개(합친 Day 17의 오후 C, 15초 소개 영상 콘티 teaser.md). 영상을 teaser.mp4로 저장해 두면 P1이 해결 장에 넣습니다.

**공식 일정표와 다르게 한 것과 이유**
| 공식 | 가이드 | 이유 |
|---|---|---|
| 팀별 피칭 | 개인별(조 안 → 조 대표) | 강사님 결정. 학생마다 자기 MVP가 있음 |
| 트랙별 피치 주제(로컬 IP × K-웰니스 / 개인화 추천 × 수요예측) | 이번 주에 만든 조사 도우미 MVP | 우리 반 진행(라라스윗과 각자 회사, Day 16 업무 간편화 MVP)에 맞춤 |
| "팀" 칸 | "함께 만든 것"(테스트해 준 사람, 에이전트가 한 일, 내가 내린 결정) | 개인 발표 |
| 슬라이드 스킬(frontend-slides 등) | P1 프롬프트가 직접 넘기는 HTML 발표를 만듦 | frontend-slides(zarazhangrui/frontend-slides, MIT)는 SKILL.md 하나가 아니라 저장소 전체(스타일 파일, 템플릿, 스크립트)가 필요해 git이나 플러그인 설치가 있어야 함. 학생 노트북(특히 윈도우)에서 git이 있는지, 데스크톱 앱에서 /plugin이 되는지 확인하지 못함. 강사님 시연으로 보여 주시려면: `/plugin marketplace add https://github.com/zarazhangrui/frontend-slides` 후 `/plugin install frontend-slides@frontend-slides`(README 기준, 시험 안 함) |
| Vercel 배포 | 아티팩트 발행이 기본, Vercel Drop은 심화 | 강사님 결정. 학생 중 Vercel을 써 본 사람 0명(실습시트) |

**Claude가 정한 것(알려 드림)**
- 오전 꼭: P0(오늘 규칙, 없으면 뼈대부터) → P1 pitch.html(9장, 키·누르기·밀기로 넘김, Chart.js 4.5.1 막대 하나, MVP 열기 버튼, 인쇄하면 PDF) → P2 script.md(3분, 데모 40초) → P3 qa.md(깐깐한 팀장 질문 8개, ★3) → 링크. 심화: 움직이는 BM 차트(데이터·서비스 트랙 공식 과제), Vercel Drop 폴더.
- 링크 버전(아티팩트)에는 teaser.mp4가 들어가지 않습니다. 발표는 각자 노트북의 pitch.html로 합니다. 영상까지 한 링크에 넣으려면 Vercel Drop.
- "MVP 열기" 버튼은 준비 구간의 링크 칸(어제 화면 링크)으로 갑니다. 비우면 mvp.html(그 노트북에서만 열림).
- 오늘 듣는 사람이 보는 세 가지(카드와 폼이 같음): 문제가 분명했나 / 데모를 보고 믿음이 갔나 / 요청사항이 분명했나. "공식 평가 점수가 아니라 서로 주는 피드백"이라고 적었습니다.
- "내 결정" 네 곳: 대본을 내 말로 / ★ 질문의 내 답 / 조 대표 정하기 / 받아들일 피드백.

## 강사님이 전날 만들 것 · 구글 폼 (전체 발표용)

forms.google.com에서 새 폼을 만들고 아래 문항을 넣은 뒤, 링크를 수업 중 단톡방에 줍니다. 응답은 강사님 시트에 쌓입니다. 발표자에게 돌려줄 때는 시트에서 발표자별로 걸러 공유합니다.

| # | 문항 | 형식 |
|---|---|---|
| 1 | 누구의 발표인가요? | 드롭다운(조 대표 이름. 당일 14:40에 채움) |
| 2 | 문제가 분명했어요 (누가 매일 무엇에 시간을 쓰는지 바로 이해됐나요?) | 1~5점 |
| 3 | 데모를 보고 믿음이 갔어요 (화면이 정말 그 일을 줄여 줄 것 같았나요?) | 1~5점 |
| 4 | 요청사항이 분명했어요 (발표자가 무엇을 바라는지 한 문장으로 말할 수 있나요?) | 1~5점 |
| 5 | 좋았던 점 하나 | 단답 |
| 6 | 고치면 좋을 점 하나 | 단답 |
| 7 | 궁금한 것 하나 | 단답 |
