# 가상 학생 시험, 화면 점검, 수강생 눈 검토

## runchain.py

가이드 HTML의 복사 상자에서 프롬프트를 뽑아, 작업 폴더에서 `claude -p`로 학생처럼 보낸다.

```bash
python3 classroom/tools/runchain.py <가이드.html> <작업 폴더> <결과.json> p00 w1+ p01+ p02+ p03+
```

- 단계 `p01`은 새 대화, `p01+`는 앞 대화에 이어서, `p05&p06`은 두 상자를 한 번에 붙여 넣은 경우.
- `TOK='{"role":"MD","pick":"경쟁사 가격 조사"}'`: 입력 칸에 적은 것처럼 파란 글자를 바꾼다.
- `EXTRA='{"x1":"학생이 직접 친 한 줄"}'` 뒤 단계에 `x1+`: 가이드에 없는 한 줄(막히면의 한 줄, 내 결정 말하기)을 시험한다.
- `APPEND=1`: 같은 결과 파일에 이어 적는다(대화를 이어 갈 때). `TOOLS='...,Skill'`: 스킬을 부르는 단계.
- 결과 json의 줄마다: 단계, 모델, 성공 여부, 걸린 초, 턴 수, 사용량, 막힌 도구(denials), 새로 생긴 파일과 바뀐 파일, 답.
- 갈래 여러 개는 쉘 스크립트에서 `( ... ) &`로 나란히 돌리고 마지막에 `wait`. 오래 걸리면 Bash의 run_in_background로 돌리고 끝나면 알림을 받는다.

## 갈래 짜는 법

| 갈래 | 왜 |
|---|---|
| 보기마다 하나(하고 싶은 일 + 고른 보기) | 결과가 직무마다 다르게 나오는지 |
| 아무것도 안 바꾼 학생 | 기본값과 수업 예시가 맞는지. W2가 "직접 골랐다"를 지어내지 않는지 |
| 보기에 없는 것을 직접 적은 학생 | 보기 밖에서도 맞는 칸과 화면이 나오는지 |
| 회사를 바꾼 학생, 일과 회사가 안 맞는 학생 | 가상 회사로 바꾸고 알리는지, 그 회사가 오후와 W2까지 가는지 |
| 테크 트랙 | 테크 직무의 결과가 나오는지 |
| 오후 메뉴를 이어서 하는 학생 | 파일 이름, 비교 기준, 백업이 꼬이지 않는지 |
| 막히면의 한 줄들 | 정말 그 한 줄로 풀리는지 |

모든 상자를 한 번 이상 돌린다. 문구를 고치면 그 상자가 들어간 갈래를 처음부터 다시 돌린다. 끝나면 발행본의 상자가 시험본과 글자 단위로 같은지 비교한다(`<pre id="...">` 내용을 뽑아 비교).

**통과 기준:** 되묻지 않고 끝까지 돈다 / 시킨 파일이 생긴다 / 답이 짧다(보고 3줄) / 가이드가 약속한 것이 실제로 나온다 / 학생이 하지 않은 결정을 했다고 쓰지 않는다.

## 이 환경에서만 생기는 일 (가이드 문제가 아님)

- 셸 명령이 막혀 있어 python으로 저장하려던 단계가 가끔 파일 없이 끝난다(학생 화면에서는 허락 창). 다음 프롬프트가 "없으면 먼저 만들고"로 이어지는지 본다.
- 쇼핑몰, 공식몰, 메타 광고 라이브러리, 채용 사이트 원문이 막혀 검색 결과 요약으로 채운다. "못 찾음"이 학생 화면보다 많게 나올 수 있다.
- 작업 폴더 경로가 길어 Claude가 경로를 잘못 적고 다른 곳에 저장했다가 고치는 일이 있다.
- 강사의 클라우드 세션은 이 환경과 같은 쪽(막히는 사이트가 비슷)이고, 학생 노트북은 다르다. 웹에 기대는 단계는 수업 중 먼저 끝난 학생 세 명에게 걸린 시간, 허락 창 수, 결과를 물어 그 자리에서 정하게 시연카드에 적는다.

## 시험 결과 화면 열어 보기

```bash
node classroom/tools/check_outputs.js <작업 폴더>/mvp.html [다른 화면.html ...]
```
시험에서 만들어진 화면을 브라우저(폰 폭)로 열어, 스크립트 오류, 폰 폭 넘침, 빈 화면을 본다. 버튼 여덟 개까지 눌러 보고 오류가 나는지도 본다. 시험기는 파일이 생겼는지만 봐서 빈 화면을 잡지 못한다(Day 17 2판에서 찾은 실패). 갈래마다 마지막 화면과 고치기 전 화면을 한 번씩 연다.

## 화면 점검

```bash
node classroom/tools/check_guide.js classroom/student-guide/dayNN.html
```
폰 폭(390)과 PC(1280, 어두운 화면)에서 넘침, 복사 상자 이름, 메뉴 링크, 처음부터 글자가 든 입력 칸, 체크 키, 입력 칸 → 파란 글자를 본다. 통과면 종료 코드 0.

## 수강생 눈 검토

```bash
node classroom/tools/guide_to_text.js classroom/student-guide/dayNN.html <스크래치패드>/guideNN.txt
```
그 글 파일을 서브에이전트 세 개(반의 유형에 맞춘 사람)에게 동시에 준다. 지시문 틀:

> 당신은 내일 이 수업을 듣는 수강생이에요. 가이드를 처음 보는 눈으로 읽고 막히거나 헷갈릴 곳을 찾아 주세요. 파일은 고치지 말고 읽기만 해요. (가이드 글 경로, 복사 상자와 입력 칸 표시 설명) 당신은 이런 사람이에요: (나이, 전공, 희망 직무, Claude Code 경험, 읽는 습관, 오늘 목표). 찾을 것: 다음 할 일이 안 보이는 순간 / 설명 없이 나온 말 / 서로 어긋나는 내용 / 프롬프트와 본문이 다른 곳 / 할 수 없는 일을 시키는 곳 / 놓칠 만큼 긴 곳. 답: 심한 것부터 최대 15개, 하나마다 어디(인용) / 무엇이 문제 / 고치는 방법 한 문장. 마지막에 잘 되어 있는 것 3가지. 가이드 글에 근거한 것만.

Day 16에서 쓴 세 사람: 비전공 콘텐츠 마케터 지망생(오전 기초만이라도), 쇼핑몰 MD 2년 경력의 이직 준비생(오후를 혼자), 테크 트랙 학생(데이터 분석가·개발자 지망, 깐깐함). 세 사람이 함께 짚은 것부터 고친다. 돌아온 지적은 원문과 대조한다(에이전트의 말은 확인 전까지 가설이다).
