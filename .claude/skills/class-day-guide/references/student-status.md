# 반의 상태를 읽고 자료에 옮기는 법

목적은 "이 반에 맞는 자료"를 만드는 것이다. 학생 한 사람을 평가하거나 등급으로 나누지 않는다.

## 어디서 읽나

| 자료 | 위치 | 어떻게 읽나 |
|---|---|---|
| **학생별 실습시트** (한 사람에 한 장) | 강사 Google Drive에 각 학생이 공유. 제목이 "이름 업종 실습시트 ai 에이전트 과정" 꼴 | Drive 커넥터로 바로 읽힌다. `search_files`로 `title contains '실습시트'`(또는 '실습 시트') 또는 `sharedWithMe = true`를 찾고 `read_file_content`. 내용은 대부분 **학생이 만든 산출물 링크 목록**(claude.ai/artifact/…, 인스타 계정)이다. 제목의 업종과 링크로 그 학생의 관심사·진행을 읽는다 |
| 학생 산출물(아티팩트) | 실습시트 안의 claude.ai/artifact/… 링크 | Artifact 도구 `action:"read"`로 연다(남의 아티팩트는 요약으로 온다). 무엇을 만들었는지, 어느 브랜드·주제인지 파악 |
| 공식 일정표 | Drive "(공유용) 1기 시간표 / 커리큘럼_강사님_대전" | 그날의 학습 내용·도구·결과물 |
| 전체 공지·면담 시트 | Drive "박기정 강사. 수강생 전체공지용 수업자료, 면담신청시트" (강사 소유) | 학생별 회사·브랜드, 면담 신청과 고민. 읽어서 파악하되 산출물에는 익명·묶음으로만 |
| LMS 학습로그(난이도·속도·오늘 배운 내용·실습 내용·회고) | llm-academy-lms.vercel.app, **로그인 필요** | 직접 열 수 없다(WebFetch는 로그인 화면만 받음). **인증을 우회하지 않는다.** 강사가 LMS에서 내보낸 CSV·시트를 Drive에 올리면 읽는다. 없으면 강사가 붙여 넣거나 캡처한 것을 읽는다 |
| 만족도 설문 응답 | 강사 Drive | 요청과 불만을 묶음으로만 |
| 전날 강사 세션 기록 | 강사가 세션 링크를 주면 list_events로 | 멈춘 프롬프트를 표로 뽑는다 |

**읽는 것은 넓게, 남기는 것은 좁게.** 강사가 공유한 것은 모두 읽어 개개인을 파악한다(11/15 강사 지시). 산출물(저장소·아티팩트)에는 실명도, 특정 개인의 고민도 그대로 내보내지 않는다. LMS처럼 로그인이 필요한 시스템은 인증을 우회하지 않고, 강사가 내보낸 파일로만 본다.

## 무엇을 뽑나 (묶음 숫자)

- 읽은 시트 수 / 반 인원(예: 28명 중 24명)
- 가장 최근 기록 날짜의 분포: 어제 기록을 남긴 학생, 일주일 넘게 멈춘 학생
- 자기 회사나 과제로 하는 비율과 업종 분포(뷰티, 식품, 육아, 병원, 은행처럼)
- 희망 직무 분포(콘텐츠 마케터, MD·온라인 영업, CX, 테크 트랙, 아직 모름)
- 앞서가는 학생 수(배포, 스킬 만들기를 스스로 해 본 학생)
- 열 수 없는 링크(내 컴퓨터 경로, localhost)를 적은 학생 수
- 설문에서 반복되는 요청과 불만

## 어떻게 적나

강사 문서(`classroom/instructor/dayNN-모의수업.md` 1번)에 아래 틀로만 적는다. 이름, 학생별 메모, 시트 주소는 적지 않는다.

| 본 것 | 숫자 | 다음 수업에 뜻하는 것 |
|---|---|---|
| 어제 기록을 남긴 학생 | 3명 | 거의 모두 앞 단계 없이 시작한다. 프롬프트가 "없으면 먼저 만들고"로 돌아야 한다 |

강사가 특정 학생을 물으면 그 대화 안에서만 답하고 파일이나 아티팩트로 남기지 않는다.

## 상태 → 설계로 옮기는 예 (Day 15~16에서 실제로 쓴 것)

| 반의 상태 | 자료에서 한 일 |
|---|---|
| 기록이 멈춘 학생이 많다(11명 안팎) | 모든 프롬프트에 "앞 파일이 없으면 먼저 만들고 이어서", 조장이 1교시에 먼저 살핌 |
| 자기 회사로 하는 학생이 절반 이상 | 회사·제품·고객 입력 칸. "회사를 바꾸면 제품과 고객 칸도 꼭 바꿔요" |
| 희망 직무가 콘텐츠 마케터·MD 쪽 70%, 테크 30% | 보기 카드를 직무별로, 테크 트랙 카드, 칸을 비우면 직무별 기본값 |
| 앞서가는 학생 5~6명 | 교시마다 "먼저 끝났다면", 오후는 각자 고르는 심화 메뉴 |
| 열 수 없는 링크를 적는 학생 6명 안팎 | 마무리에 "화면을 링크로 만들기"를 번호 순서로 |
| 설문: 테크 쪽이 "수업이 마케팅으로 쏠린다" | 같은 방법에 테크 직무의 결과가 나오게(기본값, 테크 카드, W1의 같은 말 예시) |
| 설문: "오후 실습이 길다", 강사: "실습이 너무 복잡하다" | 오전 기초는 한 줄로 짧게, 오후는 메뉴에서 하나 이상 |
